# 결정 기록과 다음 행동

상태: **준비안 작성 완료 / 구현 착수 대기**. 2026-09-09 사용자가 계획 수립 중 직접 선택하고, 해당 계획의 준비 작업 실행을 요청한 내용을 반영했다. 팀의 미결정 항목을 추천 기본값으로 대신 채우지 않는다.

## 1. 확정된 작업 기준

| ID | 결정 | 근거·적용 |
|---|---|---|
| D-01 | 개발 착수 준비까지 수행 | 문서·설계·인계·검수. 기능 구현·MVVM 전환은 후속 |
| D-02 | main 9e312bb4와 후보 8aa184e3 계속 비교 | 최종 개발 시작 SHA 미선택. 문서 브랜치는 구현 기준 아님 |
| D-03 | 화면 선별 PDF·온보딩 질문안은 전달 전 | 기존 근거로 대조 틀 작성. 수령 후 최종 범위 결정 |
| D-04 | 후보의 혼합 지도를 기본 방향으로 사용 | ko NAVER, 방문객 언어 open-vector. 코드 교체는 하지 않음 |
| D-05 | 공용 개발 API 우선, 환경 확인부터 | 전원 로컬 DB 설치를전제로 삼지 않음 |
| D-06 | MVVM은 비교 후 팀에서 결정 | 기존 Controller 보완과 Riverpod 점진 도입 비교 |
| D-07 | 첫 설계 예제는 장소 상세 → 저장 → 목록 | 두 안에서 같은 계약·검증 시나리오 사용 |
| D-08 | 보류 기능 코드·테스트·의존성 보존 | 현재 삭제·숨김 없음. 실증 진입점 숨김은 후속 구현의 권장 방향 |
| D-09 | 공통 지침은 적용 가능한 수정안으로 준비 | 개인 로컬 원본 보존, 활성 지침 변경은 채택 후 별도 적용 |
| D-10 | 준비 문서 브랜치에서 검수·보존 | 병합·배포·DB 반영·실수집·유료 호출은 이번 작업 밖 |

노션은 사용자가 따로 요청하기 전 조회·수정하지 않는다. 회의 원문·개인 일정·대형 PDF·비밀 값은 공개 문서에 복제하지 않는다.

| ID | 남은 항목 | 필요한 자료 | 결정 주도 / 검토 |
|---|---|---|---|

| G-02 | 개발 시작 SHA와 통합 목록 | 두 SHA의 MVP·의존성·검증 공백 비교 | 기술 리드 / 개발팀 |

| G-09 | 첫 병합 전 리뷰·CI·배포·DB 절차 | 현재 workflow, 정확 SHA·readiness·복구 계획 | 기술 리드 / 백엔드·PM |

지도의 기본 방향과 공용 API 우선 여부는 이제 미결정 목록이 아니다. 실제 지도 검증, 개발 환경 인수와 배포 준비가 완료됐다는 뜻도 아니다.

## 4. 다음 회의의 순서

1. 화면 선별 자료와 질문안을 수령하고 Q-01~Q-08의 충돌을 정리한다.
2. 최소 흐름을 합의하고 main·후보의 차이가 영향을 주는 기능을 고른다.
3. 공통 지침 채택 방식과 현재 개발 환경의 담당·주소·분리·접근을 확인한다.
4. 같은 장소 저장 예제를 보고 코드 기준·MVVM 방식·계정 저장 정책을 결정한다.
5. 역할별 작업 항목·리뷰·완료 조건·예상 소요를 확정한다.

자료·회신이 없는 항목은 미결정으로 남기고 독립적인 문서 보완만 진행한다. 회의 참석·역할 수락·합의가 실제로 이루어진 것처럼 기록하지 않는다.

## 5. 준비 완료와 구현 착수의 구분

문서의 링크·SHA·출처·공개 범위·초안 적용 시험을 검수하면 준비안 작성은 완료다. 구현 착수는 최소 화면, 기준 SHA, MVVM, 개발 환경, 역할별 완료 조건이 기록되고 사용자가 기능 구현을 지시한 뒤다.

보존 태그·원격 정리의 이전 결과는 [보존 목록](04-preservation.md)과 [원격 정리](05-remote-branch-cleanup.md)에 그대로 남긴다. 새로운 브랜치 삭제·PR 병합·운영 배포는 수행하지 않는다.
