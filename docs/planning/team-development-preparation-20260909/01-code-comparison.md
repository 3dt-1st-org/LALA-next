조사일: 2026-09-09, 원격·PR·선별 검증 갱신일: 2026-09-10. 원격 브랜치 SHA와 로컬 Git 객체를 대조했다. 기능 표는 코드·커밋 변경 내용에 대한 판정이며, 별도 검증 기록이 없는 행은 실행 성공을 뜻하지 않는다.

후속 선택: 사용자는 main·후보를 계속 비교하고, 지도는 후보의 혼합 구성을 기본 방향으로 삼기로 했다. 아래 초기 비교·제안과 구분하며 최신 결정은 [결정 기록](03-next-decisions.md)을 따른다. 저장 예제의 대표 파일을 두 SHA에서 다시 대조한 결과는 [MVVM·API 계약](09-mvvm-and-api-contracts.md)에 있다.

- #187: head a955c2a4377d08553033345373c15216cec4bf94, base main.
- #206: head 8aa184e375f381fa4de0a97bca82ffa3e59ba836, base는 #187의 작업 브랜치.

### 2026-09-10 선별 재검증

두 SHA를 동일한 저장·계정·API 계약 범위로 검사했다. `main`은 임시 detached worktree, 후보는 정확한 head의 clean worktree를 사용했으며 상속된 DB·클라우드·인증 설정을 배제한 CI 프로필로 API 테스트를 실행했다.

## 5. 다음 개발 기준에 대한 추천

**후보 `8aa184e3`를 조건부 통합 기준으로 추천한다.** `main 9e312bb4`는 비교·복구 기준으로 유지한다. 후보는 main의 후속선이고, 선택한 혼합 지도와 검색·일정·인증·취향의 후속 race 보완을 이미 함께 담고 있으며 정확한 head의 CI와 선별 검사가 통과했다. 미룬 기능을 삭제하지 않고 보존한다는 현재 방침과도 맞는다.

후보를 지금 팀 개발 시작 SHA로 확정하지는 않는다. 70개 커밋·201개 파일에 첫 실증 기능, 보류 기능, 오프라인 수집 계약이 함께 있고 #206이 #187 위에 쌓인 Draft PR이기 때문이다. `main`에서 일부 커밋만 임의 cherry-pick하면 검증된 race·지도·생성 코드의 의존 관계를 놓칠 수 있어 기본 경로로 추천하지 않는다.

1. 기술 리드가 #187의 커밋 묶음을 먼저 검토하고 main 반영 방식과 최종 SHA를 정한다.
