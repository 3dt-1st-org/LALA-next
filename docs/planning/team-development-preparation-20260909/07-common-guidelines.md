# 공통 지침 수정안과 문서 우선순위

상태: **적용 패키지·검증 절차 준비 / 팀 채택과 활성 반영 대기**. 사용자가 선택한 개발 방향과 2026-09-10 독립 조사·추천을 반영한 준비 산출물이다. 루트의 개인 AGENTS, 공유 템플릿, Copilot 지침, 개인 전역 설정은 덮어쓰지 않았다. 실제 적용은 팀이 공통 지침을 채택한 뒤 별도 문서 변경으로 진행한다.

## 1. 공통으로 전달할 현재 결정

- 첫 실증은 한국 방문 외국인의 진입 → 탐색 → 상세 → 저장 → 도슨트 흐름을 중심으로 선별한다.
- 역사적 비교 기준은 main 9e312bb4와 후보 8aa184e3다. #187→#206 병합 뒤 제품 코드 기준은 main e64ed058이다. 원래 준비 문서 브랜치는 구현 기준이 아니다.
- 지도 기본 방향은 후보의 한국어 NAVER·방문객 언어 open-vector다. 한국어·영어·일본어·중국어 간체·번체의 전환과 출처 표시를 검증한다.
- 공용 개발 API를 우선한다. 별도 개발 환경의 존재·분리·접근은 [환경표](08-development-environment.md)로 확인한다.
- 장소 상세 → 저장 → 목록을 첫 설계 예제로 쓴다. 첫 slice에는 기존 Controller 보완을 추천하며 팀 채택 전에는 확정으로 쓰지 않는다.
- 보류 기능의 코드·테스트·공통 의존성은 보존한다. 진입점 숨김은 후속 구현이다.
- Logto SDK, 위치의 플랫폼 분기, 접근성, 데이터 출처, 시크릿 비노출 원칙을 유지한다.

## 2. 문서를 해석하는 순서

| 우선순위 | 문서 | 적용 범위 |
|---|---|---|
| 1 | 현재 사용자의 명시적 결정과 작업 경계 | 이번 준비와 후속 착수 권한 |
| 2 | 이 준비 묶음의 README·결정 기록 | 최신 제품 방향·선택 상태 |
| 3 | 선택한 SHA의 코드·API 계약·테스트 | 구현 사실. 실행 성공은 별도 증거 필요 |
| 4 | 9/8 회의 공개 요약·9/7 보고서 식별 정보 | 제품 방향과 과거 구현·캡처의 근거 |
| 5 | 이전 UI 계약·운영 문서·기능 정의서 | 기준일·SHA·환경이 일치하는 부분만 참고 |

시안은 디자인 승인본이 아니며, 과거 테스트 통과를 현재 빌드의 인수 결과로 옮기지 않는다. 회의 원문·개인 일정·대형 PDF는 공개 문서에 복제하지 않는다. 노션은 별도 요청 전 조회하지 않는다.

## 3. 충돌별 대체 관계

| 기존 위치·전제 | 이번 수정안의 처리 | 적용 전 상태 |
|---|---|---|
| 로컬 AGENTS의 카카오 고정 | 현재 선택한 언어별 혼합 지도 방향으로 대체 | 로컬 원본 보존 |
| AGENTS.example의 NAVER 단일·main.dart 모놀리스 | main의 현황과 후보의 차이, 실제 feature 책임 분리 상태로 설명 | 템플릿 원본 보존 |
| Copilot의 단일 Mac 운영 일반화 | API·worker 운영 프로필과 CI·local 개발 프로필을 구분 | 자동 로드 파일 원본 보존 |
| 과거 UI 계약의 특정 파란색·개인 이미지·도구 금지 | 현재 디자인 재량과 공통 접근성·출처 원칙을 우선 | 문서 삭제·이동 없음 |
| 이전 A–D 독립 플로우·특수 다중 에이전트 분업 | 네 분야가 한 기능을 연결하는 역할표 사용 | 과거 운영 기록으로 한정 |
| verify가 항상 읽기 전용이라는 해석 | check / fix / build / live / deploy 구분 | 스크립트 자체는 수정 안 함 |

main을 개발 기준으로 고르면 혼합 지도 관련 후보 변경을 선별·통합할 작업이 생긴다. 지도 방향 선택이 후보 전체의 병합 승인은 아니다. 지도 제공사 요금·서비스 수준·자체 호스팅 조건은 이번 코드 조사로 검증하지 않았다.

## 4. 적용 가능한 초안

| 초안 | 적용할 위치 | 역할 |
|---|---|---|
| [공통 AGENTS 초안](proposals/AGENTS.root.md) | 저장소 루트 AGENTS.md | 공통 규칙의 기준 |
| [Claude 진입점 초안](proposals/CLAUDE.root.md) | 저장소 루트 CLAUDE.md | AGENTS와 준비 문서 읽기를 명시 |
| [Copilot 진입점 초안](proposals/copilot-instructions.md) | .github/copilot-instructions.md | 같은 규칙을 참조 |

초안 내부 경로는 **적용 후 저장소 루트 기준**이다. 현재 proposals 디렉터리에 둔 사실만으로 활성화되지 않는다. 각 도구가 모든 파일을 동일하게 자동 탐색한다고 가정하지 않는다. Codex의 AGENTS 탐색·새 세션 검증은 [공식 문서](https://learn.chatgpt.com/docs/agent-configuration/agents-md)를 기준으로 한다.

Codex 공식 지침에 따르면 새 실행·세션을 시작할 때 저장소 루트부터 현재 디렉터리까지 `AGENTS.override.md`, `AGENTS.md`, 설정한 대체 이름 순으로 디렉터리마다 최대 한 파일을 결합한다. 가까운 디렉터리 지침이 뒤에 놓여 우선하며 기본 결합 한도는 32 KiB다. 현재 공통 AGENTS 초안은 이 한도보다 작다. 적용 결과는 기존 세션이 아니라 **새 세션**에서 확인한다.

채택 후 적용 순서:

1. 적용 대상의 기존 로컬 파일을 Git 제외 위치에 복사하고 원본 해시를 확인한다. 개인 내용은 공통 초안에 섞지 않는다.
2. 초안을 각 대상에 반영한다. .gitignore의 루트 AGENTS.md·CLAUDE.md 제외 규칙을 정리해 공통 파일을 추적한다.
3. AGENTS.example의 복사 안내를 새 공통 파일 참조 안내로 바꾼다. 개인 노트는 사용자 전역 지침이나 명시적으로 전달하는 Git 제외 노트에 둔다.
4. 이 절과 README의 적용 상태를 갱신하고 관련 문서 변경만 검수·커밋한다.
5. 팀이 사용하는 도구별 새 세션에서 아래 질문을 확인한다. 한 도구의 성공을 다른 도구의 성공으로 세지 않는다.

### 적용할 정확한 변경 묶음

| 대상 | 준비된 변경 | 보존·검증 |
|---|---|---|
| 루트 `AGENTS.md` | proposals/AGENTS.root.md를 공통 기준으로 적용 | 현재 ignore된 개인 사본은 저장소 밖의 비공개 백업과 해시로 보존 |
| `.gitignore` | 루트 `/AGENTS.md`, `/CLAUDE.md` 제외 규칙 정리 | 다른 runtime·secret·개인 runbook ignore는 유지 |
| `AGENTS.example.md` | 개인 사본 복사 안내를 공통 AGENTS 참조와 로컬 전역 지침 안내로 변경 | 오래된 NAVER 단일·main.dart 모놀리스 설명 제거 |
| 루트 `CLAUDE.md` | proposals/CLAUDE.root.md를 진입점으로 적용 | 도구별 자동 탐색을 근거 없이 주장하지 않고 새 Claude 세션 검사 |
| `.github/copilot-instructions.md` | proposals/copilot-instructions.md로 공통 기준 연결 | 기존 단일 Mac 운영은 해당 runbook으로 이동·참조 유지 |

이 다섯 파일은 한 문서 PR로 함께 리뷰한다. 적용 전에 현재 루트 AGENTS의 카카오 고정과 AGENTS.example의 NAVER 단일 규칙이 모두 최신 혼합 지도 방향과 충돌함을 diff에서 확인한다. 개인 내용은 공통 파일로 옮기지 않는다. 되돌릴 때는 적용 커밋을 revert하고 각자의 비공개 사본을 다시 배치한다.

## 5. 새 세션 인수 질문

| 질문 | 기대 답변 |
|---|---|
| 지금 무엇을 만들고 어느 코드에서 시작하는가? | 제품 코드 기준은 main e64ed058. 화면·MVVM·개발 환경은 합의 대기 |
| 지도·디자인 기준은 무엇인가? | 언어별 혼합 지도 방향, 색상·배치 재량, 접근성·출처 유지 |
| 보류 기능을 어떻게 처리하는가? | 코드 보존, 현재 숨김 없음, 실증 진입점 제어는 후속 구현 |
| 로컬 검사와 API 실행은 어떻게 다른가? | CI 프로필 검사와 공용 개발 API 통합 검증 구분, 운영 기본 주소 사용 금지 |
| MVVM 방식과 첫 예제는 무엇인가? | 장소 저장 예제의 Controller 보완 추천, 팀 채택 전 일괄 전환 없음 |
| 어떤 변경에 역할별 리뷰가 필요한가? | 라우터·테마는 프론트, API 계약은 백엔드, 공유 상태·SQL·환경은 기술 리드와 관련 역할 |

이번 초안의 격리된 새 세션 검증과 실제 팀 도구 적용 상태는 [검증 기록](11-validation.md)에서 구분한다.
