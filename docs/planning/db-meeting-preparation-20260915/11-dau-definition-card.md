# LALA DAU 정의 카드

상태: **김건동 권고안 작성 완료 / 강신석 최종 확정 대기**

## 추천 정의

> **LALA DAU는 한국시간 하루 동안 인증된 계정이 핵심 가치 행동을 하나 이상 성공 완료했을 때, 계정당 한 번 집계한 고유 사용자 수다.**

핵심 가치 행동의 추천 범위는 다음 네 가지다.

1. 장소 저장 완료: `place_save_completed`
2. 일정 저장 완료: `plan_saved`
3. 저장 일정 재열기 완료: `plan_reused`
4. 도슨트 실제 재생 시작: `docent_play_started`

앱 실행, 로그인, 장소 목록 노출, 단순 상세 조회는 퍼널·보조 지표로만 사용하고 주 DAU에는 포함하지 않는다. 회의에서 나온 “실제로 핵심 기능을 사용한 사람”이라는 취지와 저장 일정 재열기 후보를 반영한 안이다.

## 집계 규칙

| 항목 | 추천 규칙 | 이유 |
|---|---|---|
| 일자 | `Asia/Seoul` 00:00:00 이상 다음 날 00:00:00 미만 | 팀·실증 보고 기준을 한 시간대로 고정 |
| 사용자 | Logto `issuer + subject`에서 만든 비식별 분석 ID | 여러 기기의 같은 계정을 한 명으로 집계 |
| 게스트 | 회원가입 필수 방향이므로 주 DAU에서 제외 | 게스트 지속 식별과 계정 연결 규칙이 미확정 |
| 성공 | 기기 또는 서버의 최종 성공 단계만 인정 | HTTP 요청·화면 렌더링을 가치 행동으로 부풀리지 않음 |
| 중복 | 같은 계정은 핵심 행동을 여러 번 해도 하루 한 명 | DAU 의미 유지 |
| 이벤트 재전송 | `event_id`로 중복 제거 | 오프라인 재전송·네트워크 재시도 중복 방지 |
| 지연 도착 | `occurred_at`의 KST 일자에 귀속하고 48시간까지 재집계 | 오프라인 사용을 반영하되 확정 시점을 제한 |
| 제외 | 내부 시험 계정, 자동화·봇, 실패·취소 이벤트 | 실증 사용과 개발 트래픽 분리 |

비식별 분석 ID는 원본 `issuer`, `subject`를 대시보드에 노출하지 않도록 서버 관리 비밀을 사용한 단방향 HMAC 등으로 만든다. IP, 정확한 위치, 원문 취향, 알레르기, 토큰은 DAU 이벤트 속성에 넣지 않는다.

## 이벤트 판정

| 이벤트 | DAU 포함 | 성공 시점 | 비고 |
|---|---:|---|---|
| `app_opened` | 아니요 | 앱 시작 | 실행 수 보조 지표 |
| `user_signed_in` | 아니요 | 인증 완료 | 가입·로그인 퍼널 |
| `place_explored` | 아니요 | 탐색 결과 표시 | 지도 이동·API 요청과 분리 |
| `place_detail_viewed` | 아니요 | 상세 화면 표시 | 상세→저장 전환의 분모 |
| `place_save_completed` | 예 | 현재 저장 정책의 최종 완료 | 기기 저장·서버 승인을 stage로 구분 |
| `plan_saved` | 예 | 일정 영속화 완료 | 일정 생성 응답과 구분 |
| `plan_reused` | 예 | 저장 일정 재열기 성공 | 회의에서 제시된 대표 후보 |
| `docent_play_started` | 예 | 기기 플레이어 재생 시작 callback | 원고·음성 HTTP 200만으로 집계하지 않음 |
| `docent_play_failed` | 아니요 | 실패 확정 | 실패율·재시도 지표 |
| `visit_feedback_confirmed` | 보조 | 결과 저장 완료 | 사용량이 쌓인 뒤 DAU 포함 여부 재검토 |

## 최소 이벤트 공통 필드

`event_id`, `event_name`, `schema_version`, `occurred_at`, `received_at`, 비식별 `analytics_user_id`, `session_id`, `app_build_sha`, `platform`, `result`를 공통 후보로 둔다. 필요한 이벤트에만 `action_id`, `place_id`, `plan_date`, `stage`, 제한된 `error_code`를 추가한다.

발생 지점과 책임은 다음처럼 나눈다.

| 범위 | 기록 책임 | 검증 |
|---|---|---|
| 화면 표시·도슨트 실제 재생 | Flutter | widget/device에서 중복 발생·callback 확인 |
| 서버 저장 승인·오류 | FastAPI | 요청 재시도와 idempotency 확인 |
| 중복 제거·KST 일자·DAU 집계 | DB/배치 | 고정 fixture와 자정·지연 이벤트 검사 |
| 실증 질문·외부 보고 정의 | 강신석 | 카드의 활성 행동과 제외 규칙 승인 |

## 결정 요청

강신석이 다음 네 항목을 확인하면 A-07을 확정할 수 있다.

- [ ] 주 DAU 행동을 위 4개로 확정한다.
- [ ] 단순 탐색·상세 조회는 주 DAU에서 제외한다.
- [ ] 회원가입 필수 기간에는 게스트를 주 DAU에서 제외한다.
- [ ] KST 일자·48시간 지연 반영·내부 시험 계정 제외 규칙을 적용한다.

하나라도 다르게 정하면 이벤트 구현 전에 이 카드와 분모·분자 예시를 함께 수정한다.

## 해석 경계

사업계획서의 DAU 최대 500명은 목표와 비용 산정 가정이다. 동시접속 500명, 하루 요청 500건, 검증된 서버 처리 능력을 뜻하지 않는다. 비용 산정은 실제 이벤트가 쌓인 뒤 `DAU × 사용자당 행동 횟수 × 행동별 앱·서버·외부 API 호출 수`로 보정한다.
