# LALA DB·서비스 모니터링 회의 준비 자료

작성일: 2026-09-15. 상태: **회의 전 준비안 작성 / 팀 결정·기능 통합 검증 대기**.

[Notion 회의용 공유 페이지](https://app.notion.com/p/2026-09-15-DB-3dba803276a480d6b174ec2e5370fb9c)

현재 DB를 설명하는 ERD와 데이터 사전, 서비스 모니터링 질문, 개발 환경 차이를 준비하였다. 코드와 운영 DB의 **구조를 읽기 전용으로 대조**하였다. 사용자 데이터 조회, SQL 적용, 기능 구현, 배포는 수행하지 않았다.

## 먼저 볼 내용

1. **코드와 서버 체크아웃은 `765570a2`로 같지만 DB 구조는 완전히 같지 않다.** canonical SQL은 18개 파일·12개 스키마·53개 테이블·471개 컬럼·7개 뷰다. 실제 DB의 같은 스키마 범위에는 50개 테이블·7개 뷰가 있다.
2. **계정·기본 취향·저장·일정·여행별 설정·방문 구조가 실제 DB에 있다.** 공통 447개 컬럼의 타입·NULL 여부와 103개 PK/UNIQUE/FK 정의, 이름 있는 CHECK 67개의 존재·검증 상태를 확인하였다. CHECK/default 표현식의 전체 동등성이나 실제 앱 동작까지 검증한 결과는 아니다.
3. **SQL 068의 채팅 테이블 3개, 기존 채팅방 컬럼 3개, 제약 2개, 명시적 인덱스 4개가 DB에 없다.** `rag.knowledge_chunks.embedding_generation`은 반대로 DB에 있으며 canonical 밖의 operator-pending SQL에 정의가 있다. 적용 이력과 재현 기준을 확인할 안건이다.
4. **기존 업무 테이블만으로 정확한 DAU·전환율·도슨트 재생 성공률을 계산할 수는 없다.** 현재 상태와 일부 사건 시각은 있지만 게스트 행동·분모·반복 행동 이력이 부족하다. 필요한 지표부터 정하고 최소 행동 이벤트를 설계하는 안을 제시한다.
5. **로컬 PostgreSQL 16 구성과 운영 15.18이 다르다.** 공용 개발 API의 현재 주소·가동 상태는 인수되지 않았다. 운영 DB의 구조를 읽었다는 사실을 개발 환경 준비 완료로 해석하지 않는다.
