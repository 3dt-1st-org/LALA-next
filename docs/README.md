## 이전 문서를 읽을 때

- `product/`, `planning/`, `operations/`, `devlogs/`에는 서로 다른 시기의 계획과 실행 기록이 함께 있다. 파일의 기준일·코드 SHA·적용 범위를 먼저 확인한다.
- 오래된 기능 정의서를 현재 구현 완료의 증거로 사용하지 않는다. 코드 존재, 테스트 결과, 실제 기기 동작을 구분한다.
- 예전 UI 승인 절차·색상·지도·운영 환경 관련 규칙에는 현재 코드 또는 회의 방향과 충돌하는 내용이 있다. 충돌을 발견하면 현재 요청과 준비 묶음을 대조하고, 임의로 구현을 변경하지 않는다.
- 노션은 사용자가 기록·공유 작업을 명시적으로 요청할 때만 접근한다. 이전에 전달받은 자료는 출처를 밝혀 참고할 수 있지만, 요청 없이 노션을 새로 열거나 그 내용을 추정해 작업하지 않는다.
- 이 입구를 만들었다고 모든 과거 문서·AGENTS·개인 스킬의 정리가 끝난 것은 아니다. 수정할 범위는 준비 묶음에서 별도로 관리한다.
